# Outcome Check

Independent outcome verification for a coding agent's completion claim. One task: save a note to the server and show it in a fresh browser session.

## Reviewer experience

1. Choose **Browser-only save**. Try saving a note in the embedded app.
2. Click **Verify independently**. The candidate's three visible tests pass, including reload. The protected checks find no server record and no note in a fresh session.
3. Switch to **Correct server save** and rerun. Both outcome checks pass.
4. Try **Weakened tests** and **Legitimate test edit**. Test changes alone do not determine the outcome.
5. On the correct implementation, enable **Simulate storage-observer outage**. The result is **Unverifiable**.

All candidates and completion claims are handcrafted. The application, browser tests, storage checks, and screenshots run live. No model credentials are required. The API accepts only the four bundled candidate IDs.

## API

`GET /health` — readiness check.

`GET /api/candidates` — task contract, candidate source and visible tests.

`POST /api/verify` with JSON `{"candidate":"browser-only"}` — execute verification and return evidence. Candidate IDs: `browser-only`, `empty-save`, `server-save`, `refactored`. Optional `"observerUnavailable":true` explicitly simulates an observer outage.

`GET /api/reports/:id` — retrieve an unexpired report. The report ID is an unguessable bearer identifier. Reports contain fictional demo data and expire; there is no user-account system.

Requests are limited to 4 KB. Arbitrary URLs, code, and extra verification parameters are rejected. Only one verification runs at a time; a busy service returns HTTP 429.

## Local development (not required for reviewers)

Node 22.16+ is required. Run `npm ci`, `npx playwright install chromium`, then `npm start`. Open http://localhost:3000. `npm test` checks verdict semantics, storage isolation, and API boundaries. With the server running, `npm run test:live` executes all four fixtures and the outage control. Use `TEST_ORIGIN` to test a deployed origin.

The Dockerfile pins Playwright and its browser image to the same version. Deploy as a single Render Docker web service, using the free plan and port supplied by Render. No environment secrets, external database, or paid model calls are needed. `/health` is the health-check endpoint. Data lives in `/tmp/outcome-check` in the container and is intentionally ephemeral.

## Trust and scope

This is a narrow evidence-producing end-to-end verifier for reviewed frontend implementations. The service and its host are trusted. It is not a hostile-code execution platform. An altered test file or a contradicted claim does not establish intent. Four deliberately constructed fixtures do not establish real-world detection accuracy.
